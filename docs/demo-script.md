# Recorded walkthrough plan

Allow about **7 minutes 40 seconds**. Use a separate scratch workspace with synthetic data. Keep passwords, API keys, the normal development dashboard and terminal environment variables off screen. Sign in before starting the capture.

## Prepare the workspace

1. Start the API and frontend from a clean clone using the [Windows setup](setup-windows.md). For semantic search, use a scratch PostgreSQL database and Redis, prepare the [local embedding cache](../README.md#local-semantic-search), and start the API and worker with matching settings. Confirm OCR and semantic availability on **Settings**. Use the independent backend/frontend ports if the regular development app is open.
2. In the scratch workspace, set `EXTRACTION_MODE=gemini` while both the API and worker are stopped, then start them and upload `sample-data/layout-invoice.pdf`. Confirm the document says `llm:gemini:gemini-3.5-flash-lite` and displays a successful provider usage audit in **History**. Bookmark the detail URL. After that job finishes, stop both processes, switch to `deterministic_demo`, and restart for the remaining demonstration. Old extraction records retain their original method.
3. Leave `invoice.pdf`, `incorrect-total.pdf`, `accounting.xlsx`, `duplicate.pdf`, `corrupted.pdf` and `ocr/multipage.pdf` ready in the file picker. The previously processed Gemini document supplies the semantic-search target. Open API docs and the checked-in [evidence report](evaluation-report.md) in separate tabs.
