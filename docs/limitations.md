# Known limitations

These are material constraints, not successful test claims.

1. **Live AI not evaluated.** A real Responses structured-output adapter is implemented and tested with mocked provider responses. No API key was available, so no live extraction accuracy, provider latency, cost or compatibility claim is made. Model defaults must be checked against the account. There is no spending cap; explicitly configure credentials before provider use.
2. **OCR quality varies.** English Tesseract 5.5.4 was verified on Windows with synthetic scans. A degraded JPEG retained all eight invoice header fields but lost both line items and required review. Mean word confidence measures recognized tokens and can remain high when tokens are omitted. Scan detection is heuristic, and heavily annotated scan pages, unusual layouts and poor resolution may need manual review. Other installed language models can be selected through configuration. Bengali accuracy, Docker OCR and 1,000-page scans have not been measured.
3. **PostgreSQL/Redis/Celery not runtime verified.** Docker CLI is installed but engine unavailable. Verified local mode uses durable SQLite and a separate background process. pgvector schema, real embeddings/indexing and cosine query code are provided but no semantic retrieval results were measured. Run the Compose services and an integration session before claiming distributed processing.
4. **No 1000-page benchmark.** PDFs are rendered one page at a time with progress, timeouts and limits. Text/source JSON is aggregated after reading; detail responses include all text/source units, and initial PDF structure parsing has no per-operation timeout. Local worker mode lacks a hard per-job process-kill supervisor. Native readers can still consume resources before checks. Default upload size is 30 MB and page cap is 1200; a 1000-page scan may exceed the upload cap. Scaling needs paginated sources, per-page checkpoints, scheduling, quotas and measured load tests.
5. **One invoice record per upload.** The deterministic parser supports common label aliases, positioned PDF fields/tables, delimited/vertical text tables and canonical spreadsheet records. It is heuristic: overlapping columns, wrapped descriptions, unfamiliar labels and arbitrary layouts can still need manual review or an evaluated AI provider. Spreadsheet comparison can select another sheet/row and map columns but does not bulk-match every row against every invoice. Multiple differing invoice records/chunk fields need manual review. Differing LLM line-item arrays across chunks are withheld as ambiguous rather than guessed. Repeated scanned headers can need review. See extraction-fix.md for the expanded layout coverage.
6. **Limited financial conventions.** Explicit amount discounts, shipping, credits and tax-inclusive schema values are supported. Percentage adjustments, complex jurisdiction-specific tax rounding, currency conversion, invoice-level and line-level discount allocation, and tax-inclusive subtotal conventions require source-specific rules. Tolerance is configurable via CURRENCY_TOLERANCES JSON. Negative credit values trigger a review warning. No accounting/legal compliance claim is made.
7. **Confidence is not calibrated.** Field confidence is null with an explicit basis; OCR word confidence is source quality, not field accuracy. LLM evidence identifies a source chunk with a short excerpt, not verified field-level token alignment. Original text is always available for review.
8. **Assessment scale search/schema.** Keyword search scans extracted text/JSON and vector queries have no ANN index. Relational entities use JSON snapshots for fields, line items and issues; future analytics would normalize these further. Migrations fix vector dimensions at 1536 initially; a dimension change requires a migration/reindex. No automatic dedup deletion, cross-tenant sharing or document deletion endpoint exists.
9. **Historical snapshots.** Correction audit is retained, but reprocessing replaces the raw extraction/source snapshot and validation issues for the document. Comparison results are immutable snapshots and must be rerun after corrections; a comparison warning does not auto-clear. Duplicate warnings are generated when processing/correcting a document and are not automatically refreshed on every related document change.
10. **Security scope.** Local assessment authentication is real but not enterprise SSO. Rate limits are process-local; byte-counted request limits still need upstream upload connection/time limits in production. Cookie logout does not revoke copied tokens. Audits are append-only through the API, not cryptographically tamper-proof. No security scan or penetration test was performed.
11. **User submission deliverables.** This session created code, docs, tests, measured evaluation and screenshots. The user subsequently authorized publishing the source to their existing GitHub repository. No site was deployed and no narrated walkthrough was recorded. Follow the submission checklist and demo script.
