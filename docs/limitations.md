# Known limitations

These are material constraints, not successful test claims.

1. **Small live AI sample.** Gemini 3.5 Flash-Lite matched 69/69 expected checks across three synthetic invoices on a confirmed free-tier project. Real-world layout accuracy, sustained throughput and project-specific quota remain unmeasured. The OpenAI-compatible adapter was tested with mocks. Settings bound usage per document. Billing and project-wide quota depend on the Google Cloud project. [Live evaluation](evaluation-report.md#gemini-invoice-extraction)
2. **OCR quality varies.** English Tesseract 5.5.4 on Windows and 5.5.0 in Docker were verified with synthetic scans. A degraded JPEG retained all eight invoice header fields but lost both line items and required review. Mean word confidence measures recognized tokens and can remain high when tokens are omitted. Scan detection is heuristic, and heavily annotated scan pages, unusual layouts and poor resolution may need manual review. Other installed language models can be selected through configuration. Bengali accuracy and 1,000-page scans remain unmeasured.
3. **Worker configuration coverage.** The isolated Windows stack exercised a Celery `solo` worker. The Docker handoff exercised a Linux prefork worker with concurrency two. Multi-worker failover, broker failover, hard time limits and sustained concurrent throughput still need testing. The stale-lease test sets up an expired lease in a disposable database, then uses the recovery and reprocess endpoints.
4. **Large PDF coverage.** Tests measured a lightweight 1,000-page synthetic digital file and a 16-page scan. The reader renders one image at a time. Source text and page JSON are still aggregated for extraction and detail responses. Initial PDF structure parsing has no independent timeout. The 30 MB upload limit and processing time limits can constrain large scans. Large diverse documents, 1,000-page scanned inputs and sustained concurrent throughput still need measurement. [PDF scale results](evaluation-report.md#pdf-scale-measurements)
5. **One invoice record per upload.** The deterministic parser supports common label aliases, positioned PDF fields/tables, delimited/vertical text tables and canonical spreadsheet records. It is heuristic: overlapping columns, wrapped descriptions, unfamiliar labels and arbitrary layouts can still need manual review or an evaluated AI provider. Spreadsheet comparison can select another sheet/row and map columns but does not bulk-match every row against every invoice. Multiple differing invoice records/chunk fields need manual review. Differing LLM line-item arrays across chunks are withheld as ambiguous rather than guessed. Repeated scanned headers can need review. See extraction-fix.md for the expanded layout coverage.
6. **Limited financial conventions.** Explicit amount discounts, shipping, credits and tax-inclusive schema values are supported. Percentage adjustments, complex jurisdiction-specific tax rounding, currency conversion, invoice-level and line-level discount allocation, and tax-inclusive subtotal conventions require source-specific rules. Tolerance is configurable via CURRENCY_TOLERANCES JSON. Negative credit values trigger a review warning. No accounting/legal compliance claim is made.
7. **Confidence is not calibrated.** Field confidence is null with an explicit basis; OCR word confidence is source quality, not field accuracy. LLM evidence identifies a source chunk with a short excerpt, not verified field-level token alignment. Original text is always available for review.
8. **Search scale and language.** BGE semantic retrieval was measured on two English paraphrase queries over a synthetic corpus. Keyword substring filtering scans text/JSON and pgvector uses exact cosine ordering. Larger collections need workload-specific benchmarks before choosing trigram/full-text and approximate vector indexes. Existing documents need reindexing when the embedding model changes.
9. **Historical snapshots.** Retry behavior depends on whether the current extraction is verified or corrected. A different retry result for a protected extraction is staged for review. Comparison results are immutable snapshots and must be rerun after corrections. Comparison warnings require review after the underlying mismatch changes. Duplicate warnings are generated during processing and correction and do not automatically refresh on every related document change.
10. **Security scope.** Local assessment authentication uses signed cookies. Rate limits are process-local. Cookie logout clears the browser cookie, and copied tokens remain usable until expiration or key rotation. Audits are append-only through the API. Dependency and secret scans passed after the dependency update. Production penetration testing and hardening remain open.
11. **PDF provenance profile.** Automatic normalization covers the supported document-level C2PA JUMBF profile and checks framing, object associations and size. Cryptographic signatures, trust chains and content bindings are outside the current check. Other attachment layouts and unsupported stream filter chains are rejected. Stream budgets, pixel caps and worker deadlines constrain processing. Native parsing in the local worker has no independent hard memory cap, and a single native call can run past a cooperative deadline. Container limits add process-level isolation. [PDF security rules](security.md#pdf-ingestion-and-content-credentials)
12. **Submission handoff.** The walkthrough recording remains pending. The reviewer run used a Windows host with provisioned system tools and verified the Linux container path. Native Linux and WSL setup remain unverified in that run. Live Gemini requires the reviewer's own key and quota.
